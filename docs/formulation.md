# 问题定义与系统边界（Formulation）

## 核心定位：直播记录、单场跟进与跨场回看

需要同时关注十余路乃至数十路直播间时，人无法同时观看多路画面或收听多路混音。`bilibili-live-monitor` 将直播转化为结构化、可追溯、可导出的房间时间线，供巡检、研究与归档使用。

基础看板聚焦文本信号；媒体保存、单场分析、跨场歌曲与观众备忘按配置使用。保留录像不等于理解画面，候选活动分类不等于认证现场演唱或证明商业效果。当前功能与默认边界见[PRD](prd.md)。

## 从双源输入到统一Item

每个房间在独立Chrome页面中运行，采集两类实时输入。

主播语音可通过实时或离线识别转为带时间窗口、处理状态和来源的文本。实时稿持续修订，不能把窗口结束当作识别准确性已经核验。原始录制与识别临时素材分别管理；具体参数见[RFC](rfc.md)。

观众弹幕直接复用该网页已有的WebSocket连接。后端解码普通、zlib与Brotli包，每条弹幕生成一个item，不额外建立弹幕连接。

两类item按事件时间混合在每房间时间线中。弹幕采用服务器事件时间，转写采用音频窗口结束时间；识别有处理延迟，因此到达时间与事件时间可能不同。类型与状态始终可区分，不能把观众弹幕当作主播语音。

完整segments、timeline与SSE事件持久化到SQLite。前端只显示最近20段识别数据和80条item，不截断数据库历史；`GET /api/export`支持按房间导出混合JSONL。

## 有效性与失败表达

音频需要满足来源有效性与连续性检查。采集与识别失败不能伪装为正常静音；无观测、零值和未知是不同结果。ASR临时素材的清理不代表持久录音被删除。

弹幕来自网页实际接收的消息；断线、网页行为和协议变化都可能造成缺口，因此不承诺全量无损归档。时间线保留收到的信息与显式识别错误，不推断未收到的内容。

## 目标使用者与当前边界

目标使用者是在Apple Silicon Mac上跟踪多个B站直播间发言与观众动态的巡检、运营、研究人员，以及需要本地SQLite或JSONL供后续分析的开发者。

平台标价不等于主播实收，累计看过不等于跨场去重观众，匿名昵称不具备UID的稳定性。活动与互动的时间共现不构成因果证明。现有通知与专项分析不推出通用告警或任意问答能力，也不承诺B站以外平台、跨平台ASR或长期无人值守稳定性。

## 无付费识别API的成本边界

本地Qwen3-ASR/MLX无需付费识别API。多路Chrome、媒体解码、本地推理和流拉取仍消耗算力、内存、磁盘与带宽；可选外部模型还有自己的调用成本。费用优势不等于没有资源成本。

## 验证结论的范围

验证同时关注计算、原始事实和页面表达。线上结果是对照，不是天然真值；一致也可能共享错误。历史短测的版本与适用范围见[test.md](test.md)，旧独立切片的累计窗口不能证明当前流式容量或长跑稳定性。
