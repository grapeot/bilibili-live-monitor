# 产品需求

核心定位见 [Formulation](formulation.md)：在Apple Silicon Mac上，将多路B站直播语音与观众弹幕转为本地混合时间线。无需付费识别API，消耗本机算力与网络。

## 采集与识别

每房间独立Chrome页面静音播放。Web Audio AudioWorklet采集独立16kHz PCM，默认每30秒切片，本地常驻Qwen3-ASR-1.7B共享串行识别。同时监听该网页已有WebSocket，解码普通、zlib和Brotli弹幕，不另建连接。

有效音频必须满足源音轨live/enabled/非mute、覆盖率90%～120%、媒体进度至少墙钟80%、缺输入不超过100ms、源mute不超过100ms且无缓冲丢样。失败明确标记，不能当作正常静音。

## 时间线与存储

每条弹幕一个item，每段转写一个item，按事件时间混合，区分类型和状态。SQLite保存完整segments、timeline和SSE事件，服务重启恢复历史但不自动开房间。原始音频只作临时处理，完成后删除。

前端显示每房间最近80条item，保留最近20段识别数据供指标展示；数据库不因显示窗口截断。支持全部或单房间JSONL导出。界面全宽，支持全屏、向下跟随与上翻暂停跟随。

## 容量与生命周期

默认房间上限10、队列20，均可配置。30路/队列60是本机实测参数。队列满时过载可见；单房间连续失败默认最多5次，有效采集后预算归零。ASR进程或通信失败对同一段重启重试一次。

`run --until`接收未来带时区绝对时间，直接自管Chrome、后端及ASR进程组；状态写入DATA_DIR/runtime.json，到期仅清理自有组。保留分步启动方式。

## 验收与边界

30个实际不同房间各至少两个有效30秒窗口，并验证静音、来源隔离、队列有界、事件恢复、弹幕与转写存储和前端跟随行为。累计有效窗口与无间隙长跑分开报告。

当前不提供视频展示、视觉理解、音频回放、告警、语义摘要、多平台或跨平台ASR，不承诺弹幕全量无损。公开材料只用虚构示例，不包含真实房间、用户名、转写、录音、截图和私有路径。
