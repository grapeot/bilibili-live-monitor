# 单主播静态歌曲目录

`python -m bilibili_live_monitor.song_catalog --config config.json` 从已完成场次生成静态歌曲搜索页、每首歌的详情页和歌曲片段索引。网页点击不访问数据库；新场次完成后重新执行构建即可。

配置包含 `scope`（单主播稳定标识）、`label`、`home_url`、`output_dir`、`state_file` 和 `sessions`。每个场次指定稳定 `id`、显示 `label`、同站点 `url`，以及已完成的公开 `snapshot` 路径。旧版页面可改用 `html` 路径，仅读取已发布图表的歌曲命中区。

沿用现有已识别片段标签，不把歌名来源登记直接视为歌曲片段。当前不能可靠区分主播演唱与播放的音乐，页面统一显示出现次数、歌曲片段与局限说明，不将底层声源分类视为事实认证。歌曲标识包含主播作用域；每次片段单独留存，重建时按时间重合延续稳定标识。歌曲页保持静态URL，回填合并产生的旧标识作为锚点别名保留。`aliases` 可显式将规范化歌名映射到同一个作品标识；不同作品不要共用映射。

每个场次可选配私有 `gift_source: {"database": "/private/source.sqlite3", "room_id": "123456"}`。构建时以只读事务查询礼物流水，统计片段开始前30秒（含）至结束后120秒（不含）的礼物件数、去重送礼人数及平台金额。免费礼物若已被采集也计入件数，金额为0；盲盒沿用结果礼物的平台标价，非实付或主播实收。每次记录显示自身窗口，同歌卡片合计对重叠窗口取并集、同一账号跨次去重，不能直接相加各次人数。未知金额、数量或身份单独计数，不伪装成确定0；缺少统计来源显示暂无数据。窗口缺少两端采样证据或内部业务报文间隔超过120秒时标注未完整覆盖，这不构成对历史采集零缺口的认证。配置和账号身份不会进入公开结果。

输出 `index.html`、`index.json`、`<song-id>/index.html`。将输出目录部署为归档主页下的 `songs/`；把 `song_navigation.with_song_navigation` 注入目标场次页即可支持 `#song=歌名&at=时间戳` 定位。新版实时页面渲染器自动注入，旧版HTML可幂等追加。未知或被移除作品的旧页面保留更新提示。

目录状态属于私有构建输入，不发布配置、原始转写、账号身份或本地路径。首次生成前保存已有目标文件；部署应使用明确文件清单，并验证歌曲页及其目标场次链接。
