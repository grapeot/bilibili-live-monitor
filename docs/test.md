# 测试与验收

## 离线测试
`pytest`覆盖房间链接归一化、API参数与错误码、数据库恢复、SSE编码和事件顺序、有界队列、停止释放排队项、迟到结果generation校验、PCM覆盖率与输入有效性、低RMS跳过、ASR同段重试与崩溃恢复、连续重连预算，以及历史WebM解码。新增弹幕普通/zlib/Brotli解码、畸形包拒绝、混合时间线去重/更新/重启，以及显示80条不截断完整JSONL导出的测试。自管截止测试用合成子进程树核验后代清理。音频与弹幕均使用合成数据；历史解码测试仍需要ffmpeg。

`ruff check src tests scripts` 检查Python；`npm run build --prefix frontend` 检查TypeScript和前端构建，当前均通过。

`python scripts/live_smoke.py --rooms 10 --segments 6 --wait-seconds 300 --output .local/result.json`执行真实多房间短测，会打开直播并使用本机算力。按启动时的切片序号建立基线，只计本轮新增有效结果，未满足时非零退出。用 `--resume .local/previous.json` 沿用同次运行原始序号基线继续等待，输出须使用另一路径以保留前一份失败证据。

`python scripts/verify_isolation.py`在两个静音页面播放440/880Hz合成音，核验PCM通道频率隔离与暂停恢复。补充原生音轨enabled=false和受控派发mute事件，核验浏览器端源mute累计计时及后端拒绝逻辑，不把断供当作正常静音。此项需要Chrome，不需要ASR模型。受控事件测试不等于验证网站自然触发mute事件的全部条件。

## 真实直播短测
通过网页发现候选房间，选择十个不同且有有效音轨的直播，每路至少处理六段30秒有效音频。检查muted=true、paused=false、音轨live且enabled、媒体进度推进、序号与窗口递增、队列有界、等待和推理耗时可见。

必须同时检查墙钟与PCM时长覆盖率90%～120%、媒体进度至少推进墙钟80%、缺输入不超过1600样本、源mute累计不超过100ms且没有缓冲丢样。少量音频不能算完整窗口，错误段不计通过。当前十路各至少六个有效窗口检查通过；首次等待超时和媒体进度停顿记录仍保留，详见 `working.md`。

候选失败要留证并替换，不算通过。静音、空转写、音乐与失败如实呈现；来源隔离用可区分音源或回听核对，不能仅凭房间字段认定。

刷新看板应保留历史；SSE 携带 Last-Event-ID 应补发事件；重启服务应恢复历史但停止旧监控。实际执行结果写入 `working.md`。

## 证据
真实房间、转写、录音、数据库、runtime manifest与截图保存在 `.local/`，不进入公开仓库。十路各六段是累计有效窗口验收，包含停顿后恢复，不代表无间隙或长期稳定性保证。

## 混合时间线与30路扩容

最终25项离线测试与前端构建通过GitHub CI。30路各至少两个有效30秒窗口检查通过，保留启动阶段未满足与续测通过的证据。弹幕实际接收并写入SQLite。真实浏览器核验全宽、上翻暂停、回到最新、全屏切换与390px窄屏无水平溢出；UI注入的合成事件只用于浏览器验证，不写数据库，结束后刷新移除。审阅修复后的30路重启首轮未满足，补充实际可播放来源后同版最终短测通过，详见working.md。

30路测试包含播放器重连，不能称为无间隙或长跑验收。网页连接的消息完整性与长期高弹幕吞吐仍需分别评估。
