## AAC跨容器时间轴与有效样本验收（2026-11-11）

- 新合同 `adaptive-pk-aac-v2`：AAC包数及按序payload摘要相同，每包绝对PTS误差仍≤1ms；不再将MKV名义duration与MP4包间隔混为有效音频跨度，也不对相邻端点各自舍入后的间隔追加1ms门限。
- 新证据绑定AAC解码配置及extradata摘要、每包有效解码样本数、逐包skip/discard样本范围。任何新增裁剪、丢样本或配置改变均拒绝归档；不以时间容差掩盖少量样本损失。旧v1回执继续执行其原合同，不补造样本证据或改标v2。
- 对无既有裁剪的末包，以实际解码样本数及采样率推导向上取整的时长，只延长不足的末包；不改payload、PTS/DTS及内部gap，不硬编码AAC每帧1024样本。合法裁剪不由修复滤镜覆盖；封装不能保留时仍拒绝并保留原片。
- 验证：音频-only真实分片14053包、14390272样本，原片SHA不变，解码PCM逐字节一致，PTS最大差500μs。合成及全套回归、独立审阅与CI结果以本次PR记录为准。

## Lessons Learned
- 当前 Chrome 上 `video.muted=true` 后，`captureStream()` 仍能获取该播放器音轨，已完成单路静音转写验证。
- 连续 WebM 后续块需要保留本周期前缀，不应作为独立音频文件解码。
- 音量 RMS 不等于 VAD，无法区分语音与音乐，音乐幻觉仍需显式说明。
- B站页面未提供可用og:image或video.poster时，直播封面可从页面初始状态的roomInfoRes.data.room_info.cover读取，头像作为备选。
- SSE长连接可能拖延Uvicorn优雅关闭，服务启动需设有限的timeout_graceful_shutdown；重启后将中断的queued/transcribing历史标为cancelled。
- 未暂停与音轨live不足以证明音频完整：必须对照真实墙钟与PCM时长，不能只以切片数量或序号递增判定采集成功。
- 多房间高频弹幕不能复用每事件拉全量state的界面刷新方式；改为SSE增量合批、卡片按房间复用，避免消息量放大网络与渲染负载。
