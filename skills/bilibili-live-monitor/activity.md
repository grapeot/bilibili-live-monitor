# 唱歌 / 讲话候选时间轴与试听修订

将完整离线ASR按块投影到趋势图，帮助观察唱歌、讲话与入场/关注的时序。此工具不推断因果，初始分类只是文本启发式候选，不是声学模型或人工真值。长篇独白可能像歌词，歌词可能有“谢谢”等词，ASR也可能漏掉歌声；必须保留不确定和混合，不以背景音乐存在就认定主播在唱歌。

```bash
bili-live activity build --trends /private/trends/data.json \
  --asr /private/asr/full_transcript.jsonl --audio --output /private/review/v1
bili-live activity verify --output /private/review/v1
# 打开v1/index.html，试听、改下拉分类、导出labels.reviewed.json后：
bili-live activity build --trends /private/trends/data.json \
  --asr /private/asr/full_transcript.jsonl --labels /private/labels.reviewed.json \
  --audio --output /private/review/v2
```

输入ASR每行需包含 `room_id`、唯一`source_key`、带时区的`start_utc/end_utc`、`relative_start/relative_end`（原片内秒）、`source_path`、原片`sha256`和`text`；可包含`rms_dbfs`。两个绝对时刻的差必须与相对偏移差一致，源片不应还在写入。当前离线归一化脚本生成此格式；不要把未经时间映射的原生文件相对时间直接当墙钟。趋势范围和ASR房间必须一致，未覆盖区间显示灰色。

仅 `label=singing` 且 `music_source=probable_live` 绘制绿色背景。`music_source` 必须区分 `probable_live`（主播现场演唱候选）、`recording`（录音、对口型或明确非主播的演唱）、`uncertain`（声源不明）、`none`（无歌曲活动证据）。播放录音、有歌词但声源不明、讲话、混合及重叠冲突均不着色，分类仍保留在数据和试听列表。没有声源字段的旧唱歌标签不能自动升级为现场演唱。无音频覆盖或可疑业务采集缺口显示灰色；有覆盖但分类未知不等于缺数据。空白不代表已确认讲话，初始约30秒粒度无法给出逐句精确边界。

每块提供`text_features`：非标点文字数、文字数/整块时长、互动关键词次数、含互动词的句子文字占比，以及口语连接词次数。界面显示密度和互动信息，供外部语义复核参考；转写密度不等于实际语速，快歌与聊天会重叠。不要用单一密度阈值或一个“谢谢”决定整块；先判断主导活动，短暂插话不强行标成混合。外部模型可以结合相邻转写进行复核，最终人工标注优先。

## 全场语义复核契约

- 两阶段执行：Flash级模型分片初判，再由主线程从头到尾逐块通读转写、分类及前后文并修正。结构校验、抽检或收到成功回执不能代替全场语义复核；听音前仍标 `semantic_review`，不能改成已试听的 `manual`。
- 每批负责30分钟核心范围，前后各带30秒上下文，相邻输入重叠1分钟。按窗口中点分配唯一负责批次；上下文窗口只作证据，不重复输出。独立云端批次可同批并行提交，实际并发仍服从用户预算和平台限制。
- 输入携带原始转写指纹、批次身份、唯一目标索引、相邻转写和全场声源线索。关键词检出的线索只是索引，不是声源结论。输出逐块保留原文证据索引、理由、活动类别、声源类别和实际模型来源。
- 查明报幕是未来计划还是当前开唱；核对换曲、暂停、暂离、原唱、放歌、对口型、连麦他人声等上下文。后文可反证前文，不能仅凭连续歌词或一句“我唱的”就确认主播现场演唱。连麦归属不清用 `uncertain`。
- 完整性校验须检查指纹与批次匹配、目标无漏无重、枚举合法、证据索引有来源。空回执或无产物不算完成；长度截断时续写同任务，短理由、每至多10块增量落盘，读回再合并。不把失败结果或旧版文件混入新批次。
- 人工纠正单独保存、最后覆盖，主线程修正不得覆盖 `manual`。页面下拉同时支持活动和声源，导出再导入两者必须一致。发布前检查绿色区间与这两个字段严格对应。

分享只生成另一个脱敏汇总包，显式允许的字段为聚合曲线、时间范围与展示色带；不上传原始 `activity.json`、完整转写、身份、私有路径或音频。先检查导出内容，再按用户授权部署、核对线上文件指纹及桌面/移动显示。私有持链接访问不是密码认证。

## 高置信度歌名与联动

`activity build --songs /private/songs.json` 可附加已核对的歌名。先用报幕及多段歌词识别候选，再由独立审阅者实际查阅歌曲歌词/正式元数据交叉核验。只有名称与歌词相符、且声源仍为现场候选的高置信度项进入展示；两者任一不确定就留空。搜索时只发送公开歌词片段/歌名，不发送观众聊天或身份。

输入结构为 `{"schema_version":1,"dataset_id":"与标注相同的指纹","songs":[{"title":"合成歌曲","confidence":"high","source_keys":["合成窗口键"]}]}`。非high项不展示；未知或重复窗口、跨数据集、非现场唱歌窗口拒绝导入。输出 `songs` 只含显示ID、歌名和时间段，不带证据原文或窗口身份。一个演唱被讲话/缺口分开时保留多段，不能用整体起止时间填平。主线程审核歌名后再投影，不让模型直接写时间覆盖。

图上唱段悬停时即时显示大字歌名和时间浮层，随鼠标移动并限制在视窗内；不依赖需要等待的原生title提示。四图下面列歌名，悬停或键盘聚焦同样显示浮层并联动高亮，点按可固定/取消。鼠标覆盖曲线/数据点时也按对应唱段显示歌名，原数值提示仍保留。活动修订后按当前绿带重新裁剪歌名段，更新按钮有效时间，不能把整首其他有效片段一起隐藏。新增数据与交互代码须做code/privacy review，分享仍从字段白名单单独生成。

`--audio`额外需要ffmpeg和ffprobe：校验原片SHA256后按每个源文件导出48kbps单声道MP3，最多两路并行；与ASR同样补齐容器时间戳空洞，原素材只读。九小时源音频大约生成200MB MP3，先确认预算和磁盘。省略该参数只生成图表/文字，试听按钮禁用。浏览器按块偏移播放，音频结束不会证明分类正确。

输出`index.html`、`activity.json`、`labels.json`、`manifest.json`，启用音频时还有`audio/`。页面可筛选和分页，修改分类立即重画四图色带；导出JSON后用CLI生成新目录，保留旧版。修订文件的`dataset_id`绑定房间、源片SHA、时间与偏移；不能跨场套用。`provenance=automatic_candidate/semantic_review/manual`区分启发式、外部文本语义复核候选与人工修改；语义复核文件沿用相同schema，通过`--labels`读取，runtime不自行调用模型。不能因为导出或验证成功就称全部人工验收。

启用音频时，同时检查块偏移落在导出的实际音频时长内（尾部容差0.2秒）。同一源片的墙钟起点必须一致；verify核验固定产物、全部引用音频及其指纹，不仅检查清单中恰好存在的条目。无音频构建只验证数据/图表，不声称已验证试听。

验收包括：范围与身份匹配、缺口保留、原片未改、verify通过；实际试听若干唱歌/讲话/混合/边界片段，核查修改后色带更新、导出再导入一致。它仍是供用户审阅的草图，未完成试听的部分必须标为候选。页面包含原转写、源信息与本地试听，默认仅本地，不自动上传或部署。分析时将来源缺口、推荐流量变化与内容变化分开，不能把色带与关注曲线相邻直接认定为因果。
