# 直播引流预告片

目标是让陌生观众在2–3分钟里看懂两三个完整事件、记住主播的特点，并有继续观看的理由。礼物峰值、长歌和高密度转写只是检索线索，不是自动入选规则。先读完整上下文，把设置、变化和反应留在一起；允许非时间顺序组合，跨事件明确换场，不能拼出没发生过的因果。

从离线ASR的`source_path`、`sha256`、`relative_start/end`回到原文件，不用开播时间减法定位跨重连素材。候选阶段每场列6–10项，说明陌生观众理解成本、叙事作用及声源，选出少数互补事件。唱段只取已确认本人演唱的完整乐句；试播原唱、他人演唱和声源不明不能冒充本人。时间映射只是初定位，首尾语句、画面和音画同步要核验后再定秒数。

先取少量画面和声音样本再渲染。快速seek出现花屏时用从文件起点解码的小样交叉验证；确认源本身损坏就换素材，不能把编码退出码0当画面通过。构图要保住主角表情，同时裁掉或持续遮住原始聊天面板、观众昵称/头像/UID、礼物人名、SC和榜单；头顶名牌、底部小人也可能暴露身份。声音里的私密身份直接删句。匿名重绘关键弹幕按下节执行；自动ASR没有逐字核准时不直接烧成对白字幕。

## 可选：放大关键弹幕

笑点或主播回应若依赖某条弹幕，先检查原画是否足够清楚、是否及时出现。原画过小或滞后时，可以在用户授权范围内匿名重绘少量必要弹幕；不是每段都要加，也不以滚屏制造热闹。只使用源记录可核对的真实原话，保留提问与回应的时间关系，不伪造留言或拼出不存在的互动。去掉昵称、头像、UID和个人信息，以独立样式标为弹幕，避免误认成主播对白。隐私不明、涉及私聊或敏感生活信息的内容不使用。当前基础CLI提供情境标题；额外弹幕层按具体项目合成，并单独复核文字、字号、遮挡与时序。

`bili-live trailer render --plan /private/edit.json --subject demo --font /private/chinese.ttf --output /private/new-output`执行已审阅的精剪表。格式示例：

```json
{"schema_version":1,"subjects":{"demo":{"title":"合成直播","clips":[{"source":"/private/source.mkv","sha256":"源文件SHA256","start":20,"end":150,"crop":[200,100,800,600],"masks":[],"label":"合成事件"}]}}}
```

每段只对应一个源文件；`crop`及可选`masks`为原画坐标的`[x,y,w,h]`，遮罩先于裁剪。带显示旋转矩阵的源先拒绝，避免自动旋转导致遮罩错位。`label`为已核实的单行情境提示或曲名，最长36字符，由Pillow生成透明图片叠加，不依赖ffmpeg的drawtext编译选项。总素材120–180秒。工具验证源指纹、实际音视频包的边界和覆盖、画幅，保持原声原速、逐段重编码为1280×720/30fps，再拼接并测量两遍响度。所有输出（包括精剪表、源路径、字体副本、日志和视频）只进私有目录，不提交公开仓库。工具不自动挑内容，不发布。

`bili-live trailer verify --output /private/new-output`核对成片指纹、逐轨覆盖、时长、H.264/AAC格式及完整解码；`contact.jpg`和每个剪点的`edge_*`供画面复核，`loudness.json`绑定成片指纹。动态归一回退默认报错；峰值受限且接受动态处理时，渲染显式加`--allow-dynamic-normalization`，回执记录实际模式，仍须试听其对声音的影响。最终AAC独立测量要求−16±1 LUFS、真峰值≤−1 dBTP（目标−1.5，留0.5 dB编码容差）。编码与测量不能代替实际听感验收。无法听音的agent必须说明限制，将首尾词、语气、音画和接点留给能够试听的人；不得声称已听过。

交付前以独立code/privacy review检查代码和新增产物，再由主线程读回、修复和验收。检查开头10秒能否看懂、前30秒是否兑现、每件事是否完整、重复信息是否可删；不能用文案补救无效素材。打开成片文件夹供用户观看。Git及发布动作遵循当次授权，用户要求切片PR不merge时保持OPEN。
